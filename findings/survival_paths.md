# Survival Paths

这个栏目记录的不是“为什么死”，而是“为什么活”。

死亡原因负责指出问题。

复活路径负责指出改法。

## 五大复活路径

### 1. 缩小用户范围

从：

```text
所有人都能用
```

改成：

```text
某一类人在某个具体时刻必须用
```

例子：

- 研究生写文献综述
- 飞书团队整理会议纪要
- 电商运营发布活动图
- 求职者投递某个岗位前

### 2. 降低输入成本

从：

```text
用户先填大量背景和参数
```

改成：

```text
上传文件、粘贴链接、选择模板、一句话开始
```

例子：

- Canva GPT：一句话生成设计稿
- Consensus：直接输入研究问题

### 3. 输出直接变结果

从：

```text
建议、思路、摘要、教程
```

改成：

```text
可发布、可投递、可编辑、可复习、可交付
```

例子：

- Canva：可编辑设计稿
- 求职产品：可投递简历，而不是求职建议
- 课程产品：可交付课程，而不是课程大纲

### 4. 接入真实系统

从：

```text
只在聊天窗口里回答
```

改成：

```text
能读取、创建、修改、导出或发送
```

例子：

- Canva 接设计系统
- Apify 接抓取平台和 Actor
- 飞书 Skills 接文档、表格、消息和审批

### 5. 从工具升级为工作流

从：

```text
帮用户完成一步
```

改成：

```text
帮用户完成一条完整路径
```

例子：

- AI 写作：从写初稿升级为选题、草稿、发布、复盘
- AI 简历：从优化简历升级为 JD 匹配、投递、面试准备
- 会议助手：从生成纪要升级为任务分配、同步项目管理工具

### 6. 从生成到执行

从：

```text
给用户建议、草稿、步骤
```

改成：

```text
在真实环境里替用户完成动作
```

例子：

- 浏览器助手：直接操作网页
- 会议助手：自动写入日历和任务
- 个人助理：管理任务和权限
- Agent 工具：执行开发、测试、部署中的具体步骤

风险：

执行越真实，信任成本越高。

用户需要：

- 预览
- 确认
- 撤销
- 权限边界
- 失败恢复

## 成功案例对照

| 项目 | 活因 |
| --- | --- |
| Canva GPT | 输出直接是设计稿，接真实系统，输入极低 |
| Consensus | 接论文数据库，用户任务明确 |
| Apify Skills | 连接真实抓取工具，输出结构化数据 |
| 飞书 Skills | 能执行动作，进入真实工作流 |
| Autai | 从建议变成浏览器执行 |
| GistGenie | 从会议摘要变成任务和日历动作 |

## 使用方式

每个尸检项目最后都应该问：

```text
它最适合走哪条复活路径？
```

如果没有任何一条路径成立，这个项目才是真正高危。
